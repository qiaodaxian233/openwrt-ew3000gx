## 三、方案 A：内存试跑（零风险）⭐ 推荐先做

**原理：TFTP 传镜像到内存 → bootm 启动 → 全程不写 flash**

### 3.1 搭建 TFTP 服务器（PC 侧）

#### 方法 1：Windows 自带 tftpd（需开启功能）

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName TFTP -All
# 或用 tftpd64：https://pjo2.github.io/tftpd64/
```

#### 方法 2：用 Python 快速起一个（推荐）

```powershell
# 保存为 tftp_server.py
```

```python
# tftp_server.py — 极简只读 TFTP 服务器
import socket, struct, os, sys

ROOT = r"E:\jiaoben\pojia\immortalwrt"
PORT = 69

srv = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
srv.bind(("0.0.0.0", PORT))
print(f"TFTP listening on 0.0.0.0:{PORT}, root={ROOT}")

while True:
    data, addr = srv.recvfrom(2048)
    opcode = struct.unpack(">H", data[:2])[0]
    if opcode != 1:      # RRQ
        continue
    parts = data[2:].split(b"\x00")
    fname = parts[0].decode()
    mode = parts[1].decode() if len(parts) > 1 else "octet"
    path = os.path.join(ROOT, os.path.basename(fname))
    print(f"[RRQ] {fname} from {addr}")
    if not os.path.exists(path):
        srv.sendto(struct.pack(">HH", 5, 1) + b"File not found\x00", addr)
        continue

    s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
    s.bind(("0.0.0.0", 0))
    s.settimeout(5)

    with open(path, "rb") as f:
        blk = 1
        while True:
            chunk = f.read(512)
            pkt = struct.pack(">HH", 3, blk) + chunk
            for attempt in range(5):
                s.sendto(pkt, addr)
                try:
                    ack, _ = s.recvfrom(1024)
                    if struct.unpack(">H", ack[:2])[0] == 4 and struct.unpack(">H", ack[2:4])[0] == blk:
                        break
                except socket.timeout:
                    continue
            else:
                print("  timeout, abort")
                break
            blk = (blk + 1) & 0xFFFF
            if len(chunk) < 512:
                break
    s.close()
    print(f"[DONE] {fname}")
```

运行：
```powershell
python tftp_server.py
```

### 3.2 PC 网络设置

把 PC 网卡设成 u-boot 网段：

```powershell
# 有线网卡（建议用网线直连路由器 LAN 口）
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.110.2 -PrefixLength 24
```

⚠️ **重要**：u-boot 默认 `serverip=192.168.110.2`，所以 **PC 必须是 192.168.110.2**。

### 3.3 u-boot 里执行

```bash
# 1) 设置网络（与默认一致，确认一下）
setenv ipaddr 192.168.110.1
setenv serverip 192.168.110.2
setenv netmask 255.255.255.0

# 2) 测试连通
ping 192.168.110.2

# 3) TFTP 拉取镜像到内存
tftpboot 0x46000000 ew3000gx-initramfs.bin

# 期望输出：
#   Loading: #####################
#   20.7 MB transferred

# 4) 启动（不写 flash！）
bootm 0x46000000

# 或指定 FIT 配置
bootm 0x46000000#config-1
```

### 3.4 预期结果

**成功**：串口刷出 OpenWrt 启动日志，最后出现：

```
Please press Enter to activate this console.
```

然后 PC 访问 `http://192.168.1.1` 打开 LuCI。

**失败**：
- `Bad Magic Number` → 镜像没传对，重新 `tftpboot`
- 卡住不动 → 硬件不兼容，看日志定位
- 内核 panic → 内存布局或 DTB 问题

**失败也没关系**：`reset` 或断电重启，回到 ReyeeOS，**flash 一个字节没变**。

## 四、方案 B：写入 flash（确认 A 成功后再做）

### 4.1 前置条件

- ✅ 方案 A 已成功启动
- ✅ 已准备好正式固件（`*-squashfs-sysupgrade.bin`）
- ✅ 备份完好（`mtd_backup\` 32.62MB）

### 4.2 ⚠️ 关键：写什么、不写什么

| 分区 | 操作 | 说明 |
|---|---|---|
| `BL2` (mtd0) | ❌ **绝不碰** | 引导第一阶段，写坏必变砖 |
| `FIP` (mtd3) | ❌ **绝不碰** | u-boot 本体，写坏失去恢复能力 |
| `Factory` (mtd2) | ❌ **绝不碰** | WiFi 校准数据，丢了信号异常 |
| `product_info` (mtd4) | ❌ 不碰 | SN/MAC |
| `u-boot-env` (mtd1) | ⚠️ 可选 | 空的，写不写都行 |
| `kdump` (mtd5) | ✅ 可写 | 崩溃日志，无所谓 |
| **`firmware` (mtd6)** | ✅ **写这个** | 15MB，kernel+rootfs |
| `kernel` (mtd7) | ✅ 可写 | 单独内核分区 |
| `rootfs` (mtd8) | ✅ 可写 | 单独根分区 |
| `rootfs_data` (mtd9) | ✅ 可写 | overlay |

**最安全：只写 `firmware`（mtd6）**，因为它是完整的 FIT 镜像。

### 4.3 操作步骤

#### 步骤 1：备份当前 firmware（再做一次，保险）

```sh
# 在现有 ReyeeOS 的 SSH 里
dd if=/dev/mtd6 of=/tmp/fw_now.bin bs=4096
# 传回 PC（用之前的 nc 方法）
```

#### 步骤 2：传入新固件

```sh
# PC → 设备
# 用 Python paramiko 或 nc
```

#### 步骤 3：写入（在 u-boot 里更安全）

```bash
# u-boot 里
tftpboot 0x46000000 openwrt-ew3000gx-squashfs-sysupgrade.bin

# 擦除 firmware 分区
sf probe 0
sf erase 0x100000 0xF00000

# 写入
sf write 0x46000000 0x100000 $filesize

# 校验（重要！）
sf read 0x50000000 0x100000 $filesize
cmp.b 0x46000000 0x50000000 $filesize
```

**`cmp.b` 是最后一道保险**——数据不一致就重写。

#### 步骤 4：重启

```bash
reset
```

## 六、重要提醒

### 🔴 绝对不能做

1. **不要写 BL2 / FIP / Factory**
2. **不要在写 flash 时断电**
3. **不要跳过 `cmp.b` 校验**
4. **不要在没备份的情况下动手**

### 🟡 必须做

1. **备份再复制一份到别的盘**
2. **第一次先走方案 A（内存试跑）**
3. **每一步都记录串口输出**

### 🟢 安全边界

只要 **BL2 + FIP 完好**，设备永远能进 u-boot，永不变砖。

## 七、快速命令速查

```bash
# ── u-boot ──
printenv                    # 看环境
help                        # 所有命令
mtd list                    # 分区表
sf probe 0                  # 探测 SPI flash
sf read  <addr> <off> <len> # 读 flash
sf erase <off> <len>        # 擦
sf write <addr> <off> <len> # 写
cmp.b <a1> <a2> <len>       # 比对
tftpboot <addr> <file>      # 网络加载
bootm <addr>[#config]       # 启动
booti <addr> <rd> <fdt>     # 启动 Linux Image
httpd                       # Web Failsafe
mtkupgrade                  # 菜单刷机
reset                       # 重启

# ── OpenWrt (initramfs 里) ──
cat /proc/mtd
mtd write <file> firmware
mtd verify <file> firmware
sysupgrade -n <file>
reboot
```

## 八、故障排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `tftpboot` 无反应 | PC 不在 192.168.110.x | 改 PC IP 为 192.168.110.2 |
| `TFTP error: not found` | 文件名不对 | 检查 tftp_server.py 的 ROOT |
| `Bad Magic Number` | 镜像损坏 | 重新传输，核对 sha256 |
| 卡在 `Starting kernel` | DTB/内存不匹配 | 检查 load 地址 0x48000000 |
| kernel panic | 分区表不符 | 用我们生成的 DTB |
| WiFi 没信号 | Factory 分区丢了 | 从备份恢复 mtd2 |
