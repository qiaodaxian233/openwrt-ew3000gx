## 二、为什么同 SoC 的 RG-X30E 固件不能直接刷

| 项 | RG-X30E（社区已有） | RG-EW3000GX（本机实测） |
|---|---|---|
| SoC | MT7981B | MT7981（同） |
| 闪存 | **SPI-NAND 128MB** | **SPI-NOR 32MB** |
| 控制器 | `spi_nand` | `spi@11009000`（**SPI2**） |
| 管理 | `mediatek,nmbm` + UBI | **固定分区，无 UBI** |
| 引导副本 | FIP + **FIP2** 双份 | **单 FIP** |
| 分区 | BL2/uboot-env/Factory/FIP/FIP2/product_info/kdump/ubi | BL2/uboot-env/Factory/**FIP**/product_info/kdump/firmware |
| 内核/rootfs | UBI 卷内分离 | **FIT(kernel+fdt) + 紧随的 squashfs** |
| 能否直刷 | — | ❌ 内核找不到 UBI 会 panic |

## 三、本机实测硬件（来自原厂 fdt@1，权威）

```
compatible  = mediatek,mt7981-spim-nor-rfb
model       = MediaTek MT7981 RFB
bootargs    = console=ttyS0,115200n1 loglevel=8 earlycon=uart8250,mmio32,0x11002000
```

### 闪存与分区（`spi@11009000` → `spi_nor@0`）

| label | 起始 | 大小 | 备注 |
|---|---|---|---|
| BL2 | 0x000000 | 0x040000 | |
| u-boot-env | 0x040000 | 0x010000 | |
| Factory | 0x050000 | 0x010000 | WiFi 校准 |
| **FIP** | **0x060000** | **0x080000** | 注意：在 Factory 之后 |
| product_info | 0x0E0000 | 0x010000 | SN/MAC |
| kdump | 0x0F0000 | 0x010000 | |
| **firmware** | **0x100000** | **0xF00000** | 15MB，装 FIT+squashfs |

- `spi-max-frequency = 0x3197500` = 52 MHz，quad（tx/rx buswidth 4）
- **无 `read-only` 属性**（原厂 DTB 里分区没设 read-only）

### 原厂 FIT 内部结构（`mtd6_firmware.bin`）

```
FIT @0x0  totalsize=0x2A1A10  version=17
/  timestamp / description="ARM64 OpenWrt FIT (Flattened Image Tree)" / #address-cells
  images
    kernel@1   description="ARM64 OpenWrt Linux-5.4.194"  data=2740356B
               type=kernel arch=arm64 os=linux compression=lzma
               load=0x48080000 entry=0x48080000
      hash@1 (crc32) / hash@2 (sha1)
    fdt@1      description="ARM64 OpenWrt EW3000GX-PRO device tree blob" data=16945B
               type=flat_dt arch=arm64 compression=none
      hash@1 / hash@2
  configurations
    default = config@1
    config@1  description="OpenWrt" kernel=kernel@1 fdt=fdt@1
FDT_END
```

**关键结论：FIT 里没有 rootfs 子镜像**，squashfs 是 FIT 之后独立追加的：
- FIT 结束于 `0x2A1A10`
- squashfs magic `hsqs` 出现在 `0x2C0000`（对齐到 128K 边界）
- FIT 内 **无 signature 节点**（只有 crc32 + sha1 两种 hash），u-boot 不强制验签

这决定了 OpenWrt 镜像必须用 `append-kernel | pad-to 128k | append-rootfs` 组装，而不是纯 FIT。

### 网络与交换

```
ethernet@15100000 (mediatek,mt7981-eth)
  mac@0  phy-mode = 2500base-x  fixed-link speed=2500
  mdio-bus
gsw@0 (mediatek,mt753x)  status=okay
  port@6  phy-mode=sgmii
  reset-gpios = <&pio 54 GPIO_ACTIVE_HIGH>
hnat: mtketh-wan="eth0.1"  mtketh-max-gmac=2
```

### GPIO / LED / 按键

| 功能 | GPIO | 极性 |
|---|---|---|
| reset 键 | pio 1 | ACTIVE_LOW |
| mesh 键 | pio 0 | ACTIVE_LOW |
| sysled 红 | pio 13 | ACTIVE_LOW |
| sysled 绿 | pio 6 | ACTIVE_LOW |
| meshled | pio 5 | ACTIVE_LOW |
| mt7531 reset | pio 54 | ACTIVE_HIGH |

### UART（接串口的依据）

`serial@11002000` (uart0) `status=okay`，bootargs 明确 `console=ttyS0,115200n1`。
**CH340 的 TX→板 RX、RX→板 TX、GND→GND，3.3V 电平，不要接 5V。**
