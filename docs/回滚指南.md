# 回滚指南 —— 从 OpenWrt 回到原厂 ReyeeOS

## 前提条件

**必须有的备份文件：**

| 文件 | 大小 | 说明 |
|---|---|---|
| `mtd6_firmware.bin` | 15 MB | **最关键**，完整的原厂固件 |
| `mtd3_FIP.bin` | 512 KB | u-boot，写坏就砖 |
| `mtd0_BL2.bin` | 256 KB | 引导第一阶段，写坏必砖 |
| `mtd2_Factory.bin` | 64 KB | WiFi 校准数据 |

**如果没备份：** 只能找同型号机器 dump，或者联系售后。

---

## 方式一：OpenWrt 里直接刷回（最简单）

```bash
# 1. 上传原厂固件到 /tmp
scp mtd6_firmware.bin root@192.168.2.1:/tmp/

# 2. SSH 进去
ssh root@192.168.2.1

# 3. 写入 firmware 分区（mtd6）
mtd write /tmp/mtd6_firmware.bin firmware

# 4. 校验（重要！）
mtd verify /tmp/mtd6_firmware.bin firmware
# 输出 "Success" 才算成功

# 5. 重启
reboot
```

**风险：** 如果写入过程中断电，设备会变砖，需要 UART 救。

## 方式二：u-boot 里刷回（最安全）

### 2.1 进 u-boot

1. 接 UART（CH340G，**3.3V 电平**）
2. 串口参数：`115200 8N1`，无流控
3. 上电，看到这行立刻按任意键：

```
Hit any key to stop autoboot:  2
```

### 2.2 设网络

```bash
setenv ipaddr 192.168.110.1
setenv serverip 192.168.110.2
setenv netmask 255.255.255.0
ping 192.168.110.2
```

**PC 侧：**

```powershell
# Windows
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.110.2 -PrefixLength 24
```

```bash
# Linux
sudo ip addr add 192.168.110.2/24 dev eth0
```

### 2.3 起 TFTP 服务器

```python
# tftp_server.py
import socket, struct, os

ROOT = r"E:\jiaoben\pojia\RX_EW3000GX_fw\03_数据备份"
srv = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
srv.bind(("0.0.0.0", 69))
print("TFTP on :69, root=%s" % ROOT)

while True:
    data, addr = srv.recvfrom(2048)
    if struct.unpack(">H", data[:2])[0] != 1:
        continue
    parts = data[2:].split(b"\x00")
    fname = parts[0].decode()
    path = os.path.join(ROOT, os.path.basename(fname))
    print("[RRQ] %s" % fname)
    if not os.path.exists(path):
        srv.sendto(struct.pack(">HH", 5, 1) + b"Not found\x00", addr)
        continue
    s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
    s.bind(("0.0.0.0", 0)); s.settimeout(5)
    with open(path, "rb") as f:
        blk = 1
        while True:
            chunk = f.read(512)
            pkt = struct.pack(">HH", 3, blk) + chunk
            for _ in range(5):
                s.sendto(pkt, addr)
                try:
                    ack, _ = s.recvfrom(1024)
                    if struct.unpack(">HH", ack[:4])[1] == blk:
                        break
                except socket.timeout:
                    continue
            blk = (blk + 1) & 0xFFFF
            if len(chunk) < 512:
                break
    s.close()
    print("[DONE] %s" % fname)
```

### 2.4 刷写

```bash
# 探测 flash
sf probe 0

# 传固件到内存
tftpboot 0x46000000 mtd6_firmware.bin

# 擦除 firmware 分区（0x100000 起，0xF00000 长）
sf erase 0x100000 0xF00000

# 写入
sf write 0x46000000 0x100000 $filesize

# 校验（关键！）
sf read 0x50000000 0x100000 $filesize
cmp.b 0x46000000 0x50000000 $filesize

# 重启
reset
```

**`cmp.b` 输出 `Total of X bytes were the same` 才算成功。**

## 方式五：编程器（终极手段）

**只在连 u-boot 都进不去时用。**

### 需要

- CH341A 编程器（约 20 元）
- SOP8 测试夹（免拆焊）
- 或者热风枪拆芯片

### 步骤

1. 夹住 flash 芯片（`en25qx128a`）
2. 用 `flashrom` 或 `AsProgrammer` 读出现有内容（确认能读）
3. 写入 `mtd0_BL2.bin` + `mtd3_FIP.bin` + `mtd6_firmware.bin` 到对应偏移
4. 校验
5. 装回，上电

```bash
# Linux + flashrom
sudo flashrom -p ch341a_spi -r full_dump.bin    # 先读
sudo flashrom -p ch341a_spi -w restore.bin      # 再写
```

**`restore.bin` 必须是完整的 16 MB 镜像**，按分区偏移拼好：

```
0x000000  256 KB  mtd0_BL2.bin
0x040000   64 KB  mtd1_u-boot-env.bin
0x050000   64 KB  mtd2_Factory.bin
0x060000  512 KB  mtd3_FIP.bin
0x0E0000   64 KB  mtd4_product_info.bin
0x0F0000   64 KB  mtd5_kdump.bin
0x100000   15 MB  mtd6_firmware.bin
...
```

## 救砖判断表

| 现象 | 原因 | 救法 |
|---|---|---|
| 上电无任何反应，灯不亮 | BL2 坏了 | 编程器刷 `mtd0_BL2.bin` |
| 灯亮，串口无输出 | FIP 坏了 | 编程器刷 `mtd3_FIP.bin` |
| 串口有 u-boot，但启动失败 | firmware 坏了 | u-boot 里重刷 `mtd6` |
| 能启动，但 WiFi 没信号 | Factory 丢了 | 刷 `mtd2_Factory.bin` |
| 能启动，MAC 全 `00:00:00` | product_info 丢了 | 刷 `mtd4_product_info.bin` |
| 能进 OpenWrt，但配置乱 | overlay 坏了 | `firstboot && reboot` |

---

## 保险建议

1. **备份存三份**：本机、移动硬盘、网盘
2. **刷机前再备份一次** `mtd6`
3. **第一次用 initramfs 试跑**（内存启动，不写 flash）
4. **不要在雷雨天/断电频繁时刷机**
5. **准备 CH340G**（10 块钱，救命用）

---

## 安全边界

**只要 `BL2` + `FIP` 完好，设备永远能进 u-boot，永远能救。**

所以：

- ❌ 绝对不要写 `mtd0`（BL2）
- ❌ 绝对不要写 `mtd3`（FIP）
- ❌ 绝对不要写 `mtd2`（Factory）
- ✅ 只写 `mtd6`（firmware）
